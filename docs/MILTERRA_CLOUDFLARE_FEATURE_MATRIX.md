# Milterra Cloudflare feature and compatibility matrix

Source audit on 25 September 2026 at `f1cad83`. This records what is wired in the checkout, not what has passed a live commercial acceptance test. `W` means the route/UI is implemented and has focused local tests; `P` means partly wired or dependent on configuration/provider acceptance; `T` means development/test content only; `I` means present but disabled by default. Risk is the **migration effort/correctness risk** for a Pages + Python Workers + D1 + R2 deployment, not the current production incident level. New Workers/D1 tests remain necessary for every migrated feature.

The registered API is one FastAPI application with all router families loaded by [`main.py`](../backend/app/main.py#L200-L240), not a standalone store service. The Flutter router likewise has customer, seller, admin, farmer, vet, cooperative, collection and purity screens in [`router.dart`](../mobile/lib/app/router.dart). Preserve those routes or make any narrower deployment boundary explicit; removing them is not a storefront migration.

## Runtime blockers and proof points

| Current dependency or behavior | Evidence | Required Cloudflare proof or replacement |
| --- | --- | --- |
| FastAPI with Uvicorn/Docker startup | [`requirements.txt`](../backend/requirements.txt), [`main.py`](../backend/app/main.py#L90-L149) | Cloudflare [documents FastAPI in Python Workers](https://developers.cloudflare.com/workers/languages/python/packages/fastapi/), but this app's lifespan, mounts, imports and full bundle still need a `pywrangler` build and runtime test. |
| Async SQLAlchemy + asyncpg/PostgreSQL + Alembic and PostgreSQL UUID/JSON types | [`database.py`](../backend/app/database.py), [`requirements.txt`](../backend/requirements.txt), [`alembic/versions`](../backend/alembic/versions) | **Blocker for direct port.** Cloudflare [documents no async SQLAlchemy ORM support in Python Workers](https://developers.cloudflare.com/hyperdrive/examples/python-workers/). Write D1 schema/import and a compatible data layer; prove D1 binding, parameterized read/write, indexes, uniqueness and foreign keys. |
| Row locks and `SKIP LOCKED` | [`orders.py`](../backend/app/api/orders.py#L143-L167), [`shipment_tracking.py`](../backend/app/api/shipment_tracking.py#L283-L305) | Implement guarded D1 stock transitions, atomic failure of a multi-line order, job claim/lease and recovery; D1 [prepared statements/batches](https://developers.cloudflare.com/d1/worker-api/d1-database/) are available, but current lock semantics do not transfer. |
| Redis production auth limiter | [`config.py`](../backend/app/config.py#L113-L143), [`auth_rate_limit.py`](../backend/app/services/auth_rate_limit.py) | Replace with a shared Cloudflare-compatible limiter with fail-closed behavior before disabling Redis requirement. | In-process unpaid-order and shipping loops | [`main.py`](../backend/app/main.py#L113-L136), [`orders.py`](../backend/app/api/orders.py#L677-L745), [`shipment_tracking.py`](../backend/app/api/shipment_tracking.py#L283-L466) | Replace with scheduled bounded batches, durable intent/lease records and recovery.
